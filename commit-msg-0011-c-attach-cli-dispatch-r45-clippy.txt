fix(octo-cli): RFC-0011-c §F.6 R4.5 — tighten u64 cast to u64::try_from (clippy)

DRY review R4 surfaced a §Scope review finding for the
spawned_at_unix cast at line 1062. R3.5 fixed the same defect
pattern at line 1556 (the since_unix cast) but missed this line.
R4.5 initially replaced 'as u64' with
'i64::try_from(h.spawned_at.timestamp()).map(i64::cast_unsigned).unwrap_or(0)'
which clippy rejected as a useless conversion (timestamp already
returns i64 so try_from is identity). Tightened to the
unambiguous defensive form.

crates/octo-cli/src/commands/agent.rs:

- line 1067 spawned_at_unix: replace redundant
  'i64::try_from(i64).map(i64::cast_unsigned).unwrap_or(0)'
  with 'u64::try_from(i64).unwrap_or(0)'. semantically equivalent
  for the i64 ≥ 0 case, defensive against future substrate
  changes allowing negative timestamps, no clippy lint

Rationale comment block above the field is unchanged (still
explains the wrap-around hazard the cast avoids).
