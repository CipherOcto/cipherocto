fix(octo-cli): R4.5 review fixes on octo agent run substrate wiring

Five-len DRY R4 round surfaced 2 HIGH + 9 MED + 4 LOW findings
across correctness, layer-model, simplification, hygiene, and
substrate-faithfulness lenses. R4.5 lands the in-scope fixes
and defers the cross-mission ones to a follow-on cycle.

HIGH severity fixes:

1. output.rs render_with_redaction: redacted bool semantic
   inversion. The pre-render builder flag stayed in the output
   JSON regardless of whether the redactor actually altered
   any payload field. Per RFC-0011-c section 9.4, redacted must
   be true when any payload field has been altered by the
   redactor. Fix: redact.rs apply now returns bool indicating
   alteration. render_with_redaction overwrites the JSON
   tree's redacted field when apply reports a mutation. The
   output reflects post-redaction ground truth rather than
   the pre-render builder flag.

2. tests/agent.rs: stale tv_agt13b_run_subcommand_is_pending
   stub removed. The stub expected exit 64 follow-on mission
   stderr but the run subcommand is now wired. The test
   failed with exit 2 NoActiveIdentity because the handler
   runs the full dispatch path. Wired-handler coverage
   already exists in the run_exit_code_slots_pinned and
   related tests.

MED severity fixes:

3. agent.rs: transition_agent import switched from
   octo_wallet::agent::transition_agent to the facade
   octo_wallet::transition_agent at both run and destroy
   handlers. Per layer-model principle, the CLI consumes
   substrate types only through the public facade re-exports.

4. agent.rs: removed single-use map_invalid_state_transition
   helper. The helper was called from exactly one site
   (map_transition_wallet_error InvalidStateTransition arm)
   and used format Debug to_lowercase which is a parallel
   abstraction duplicating what the substrate canonicalizes
   via AgentState::as_str. Fix: inline the helper. Use
   from.as_str().to_string() and to.as_str().to_string()
   per the substrate canonical lowercase label form.

5. agent.rs: renamed agent_redactor to build_agent_redactor
   for verb-first-noun consistency with the parse and map
   helper families in mod common. Three call sites updated
   (create, destroy, run).

6. agent.rs Run variant doc + mod run module doc: aligned
   the detach default statement with the clap default. The
   substrate-faithful default is detach false (in-process).
   The CLI terminates the handle when dispatch returns.
   Two doc-comment sites claimed default-detached which
   contradicted the clap default_value_t = false. Both
   rewrites make the in-process default the canonical
   statement.

7. agent.rs run::handle: InvalidAttachHandle misroute
   collapsed into the RuntimeSpawnFailed match arm via a
   pipe-pattern. Both arms build the identical OctoCliError
   expression so they share the same handler. The substrate
   authoritatively separates them at the dispatch boundary
   (InvalidAttachHandle is exit 49 in octo-runtime error
   map) but the CLI-shape mapping collapses them because
   the spawn step is atomic from the CLI perspective and
   attach_handle is passed as None in Phase 1.

8. agent.rs run::handle: idempotent self-transition skips
   spawn_agent. Previous code unconditionally called
   runtime_spawn_agent which minted a duplicate
   RuntimeHandle for the same agent on Running to Running
   no-op. The previous handle's broadcast subscribers were
   orphaned. octo agent attach against the same agent_id
   would not see events on the new channel. Fix: detect
   idempotent self-transition via receipt.audit_log_entry
   equal to zeroed hash and receipt.previous_state equal
   to receipt.current_state, skip spawn, surface None for
   the runtime_handle output field. AgentRunOutput.runtime_handle
   is now Option RedactedIdentifier. spawned_at_unix falls
   back to 0 on the no-op path with documentation noting
   Phase 2 will route through a substrate-side
   get_or_create pathway.

LOW severity fixes:

9. agent.rs run::handle: collapsed spawn-error match arms
   for RuntimeSpawnFailed and InvalidAttachHandle into a
   single pipe-pattern arm.

10. agent.rs run::handle: timestamp panic comment refined.
    The previous comment claimed try_into unwrap_or(0u64)
    would have panicked on a pre-1970 timestamp but
    unwrap_or is the safe variant that returns the fallback
    on Err not the panicking unwrap. The as u64 cast is
    well-defined for any i64 (two complement wrap, no
    panic). Comment now documents the substrate invariant
    observation that drives the as u64 choice over try_into.

11. agent.rs tests: removed redundant .clone() calls on
    destructured from and to locals in
    run_invalid_state_transition_from_terminated_to_running_echoes_labels.
    The match at line 1666 destructures &e which creates new
    shadowed bindings, not the outer locals, so the clones
    were unnecessary.

12. agent.rs tests: schemars runtime_handle assertion
    generalized to accept either JSON Schema type string
    or oneOf / array-of-types shapes that include string.
    The field changed to Option RedactedIdentifier so the
    schema renders as a nullable string rather than a plain
    string. The test stays substrate-faithful across
    schemars versions.

13. tests/agent.rs: removed 3 orphan sibling stubs
    (tv_agt13 list, tv_agt13c destroy, tv_agt13d attach)
    whose parent missions closed without removing the
    follow-on-mission stubs. The stubs expected exit 64
    follow-on mission stderr but the subcommands are now
    wired in their respective missions. The stubs fail
    with exit 2 because the handlers run the full dispatch
    path. Wired-handler coverage exists in each
    sibling mission's tests.
