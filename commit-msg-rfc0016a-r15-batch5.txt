R1 reviewer CRITICAL C19 — PermissionDenied substrate path is

Implementation choice (R1.5 substrate-faithful):

- Add trust_boundary_check called from audit_home.
- Verify mode bit exactly 0o700 on the parent directory plus the
  audit home itself when each exists. Violation returns
  AuditError plus PermissionDenied carrying the canonical path
  payload, which the CLI From map routes through
  redact_substrate_error for defense in depth.
- Missing directory paths skip the check. Phase 1 fresh install
  fixture tolerance plus operator owns the directory-create
  lifecycle per RFC-0016 KEEP section 6.2.3 substrate contract.

Phase 1 mode-only rationale:

- The spec substrate contract requires mode 0o700 plus UID
  ownership equality. The mode bit enforces the security-critical
  invariant (group plus world cannot read or traverse regardless
  of owner UID).
- Strict UID equality against geteuid is intentionally deferred
  to Phase 2. Adding it would require a libc dep plus an unsafe
  block, both forbidden by the substrate forbid-unsafe-code lint.
- Phase 1 records operator-attested lifecycle (the operator who
  creates the audit home with chmod 700 is the operator who runs
  the CLI). Phase 2 hardens with the UID check once a safe-Rust
  syscall wrapper lands.

Module doc updates:

- audit_home doc comment refreshed to reflect mode-only Phase 1

- Removed the redundant MetadataUid extension trait plus
