# RFC-0968 AC Audit — 2026-07-27

> Mission `claimed/0968-reputation-persistence.md`. Cross-references
> the 316-line AC file in `missions/claimed/` line-by-line and reports
> what is landed vs. what remains as backlog.

## TL;DR

Phases 1–4 trait and store surface are **substantially landed**:
the `ReputationStore` trait exposes all 18 methods (4 federation
methods + quorum + catch-up), the in-memory + stoolap backends
implement them, the `election_priority` + `cross_layer_query`
adapters are RFC-0968 §10 / §22-compatible, the dual-read cutover
gate + 0.999 parity threshold are wired through `parity.rs`, and
the 13 reputation BLAKE3 domain separators + governance-set
separator live in `constants.rs`.

However, the AC file (updated 2026-07-26 with RFC-0968-A1 + A2
amendments) is **aspirational**: it asserts 57-variant
`ReputationError`, full `RecorderState` enum with 7 variants,
`DfpBytes` 24-byte wire newtype, `Clock` trait at the RPC
boundary, recorder-lifecycle hardening, and several
consolidation checkpoints. The current error enum has 22
variants under different discriminants than the AC requires,
and many of those AC surface items are not in code yet.

This document maps each AC bullet to a concrete state and lists
the gap as a follow-on work item.

## Backlog (RFC-0968 AC items NOT landed)

This backlog is the next mission-worthy work. Recommended
decomposition:

1. **0968-d-error-enum-rename-and-extend** — wholesale renumber
   of `ReputationError` from 22 to 57 variants per AC line 48,
   with all consumer crates updated. Cross-cutting.
2. **0968-d-recorder-lifecycle** — `RecorderState` 7-variant
   enum + transitions + escalation N=2..=10 + per-recorder
   severity counter (`severity_emitted_total`) + per-subject
   admission gates including `SelfDealingEvidence = 0x31`.
3. **0968-d-tombstoned-replay** — `RotationProvenanceMissing =
   0x39` test plus `ReplayRecord.rotation_provenance` wire field
   + `consume_rotation_receipt` flow with rotation tuple locks.
4. **0968-d-clock-boundary** — `pub trait Clock { fn now_unix()
   -> u64 }` at the RPC boundary + remove caller-supplied
   `now_unix` args from public RPCs (trusted-clock API per
   amendment 27).
5. **0968-d-auth-types** — `RecorderRegistrationRequest`,
   `ReaderAuth`, `AuditorAuth`, `RetentionAuth`,
   `GovernanceRegistry`, `GovernanceError` + `RETENTION_ROLE`
   bitfield.
6. **0968-d-normalizer** — `Normalizer` trait + `NormalizerInput`
   + `MAX_SEVERITY` + drift-second constants.
7. **0968-d-cargo-features** — add `mon`, `dc`, `marketplace`,
   `wallet` feature flags to `octo-reputation/Cargo.toml`.
8. **0968-d-provider-compat** — `ProviderReputationRegistryCompat`
   per mission `open/0968-b` Phase A.
9. **0968-d-presentation** — `reputation_score_0_100` with
   `Result<u8, ReputationError>` + 101-unique-values test per
   mission `open/0968-b` Phase C.
10. **0968-d-cli** — `quota-router reputation show --did <did>`
    per mission `open/0968-b` Phase E.

Items 1-3 are infrastructure (any consumer of `ReputationError`
must update). Items 4-7 are additive (no renumbering).
Items 8-10 are downstream of the `open/0968-b` mission and
cross-reference that plan.

## What this audit does NOT cover

- Adversarial review of the `Dfp` semantics
  (`determin::Dfp` IEEE-754 + canonical blob pinning) — that
  audit lives in the commit history of `determin/tests/`.
- Stoolap backend correctness vs RFC-0968 §5 schema (the 7
  migrations + indexes) — separate audit needed.
- On-chain anchoring (`missions/claimed/0968a-reputation-anchoring.md`,
  binding patch in `missions/claimed/0968a2-reputation-anchoring-binding.md`)
  — deferred to RFC-0955 acceptance.
