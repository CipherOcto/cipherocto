## RFC-0205 — Stoolap Fork Stability Certification

### CRITICAL (7)

- **§Adversary Analysis row 10 PHANTOM** (security) — TV-0205-09 cites row 10 but table has only 9 rows. Add row 10 OR drop cross-ref.
- **TV-0205-04 cargo source `#<version>` suffix** (correctness) — cargo `.packages[].source` always ends with `#<fork-version>` (verified `git+https://github.com/CipherOcto/stoolap?branch=feat/blockchain-sql#80fd701d3d843bcd30f0358ca412273aa4770f41`); strict `==` against `?rev=<sha-0>` ALWAYS fails. Use `startswith` or include `#<version>` in constant + param read from fork repo Cargo.toml.
- **TV-0205-14 FPR regex on wrong line** (correctness) — regex `gpg: Good signature from .* ([A-F0-9]{40})` extracts from wrong line. `git verify-tag` puts FPR on `using RSA key <FPR>` line. Anchor on `using (RSA|EDDSA|ED25519|DSA) key ([A-F0-9]{40})`.
- **TV-0205-05 leg c 2-step missing extraction** (correctness) — `grep -E 'Good signature from'` does NOT extract FPR. Replace with `git verify-tag | grep -oE 'using [A-Z]+ key [A-F0-9]{40}' | awk '{print $3}' | sort -u | while read fpr; do grep -F "$fpr" trusted-keys.txt; done` count ≥ 2.
- **§Determinism Requirements row 4 + Bump Acceptance Criteria item 2** (correctness) — claim "byte-equal across stable/beta/nightly rustc" technically impossible. Rust embeds RUSTC_VERSION/LLVM revision in artifact. Scope to single rustc + SOURCE_DATE_EPOCH, OR compare behavioral test-result hashes instead.
- **SOLE-consumer claim false at 5 sites** (correctness) — L20, L65, L123, L132, L183, TV-0205-02 all claim "octo-storage-core is SOLE direct fork consumer" but 12 crates carry direct `stoolap = { git = ... branch = "feat/blockchain-sql" }` today. v1.3 changelog repeats false claim.
