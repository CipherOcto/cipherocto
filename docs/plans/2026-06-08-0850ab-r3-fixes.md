### Task 3: C3 — Replace `Drop` thread with shutdown channel

**Files:**

- Modify: `crates/octo-adapter-telegram/src/real_client.rs:578-599`

**Problem (C3):** `Drop` spawns a detached thread with a fresh `current_thread` runtime to call `tdlib_rs::functions::close(client_id)`. This is wrong: it can race with the receive loop, leak the thread, and may not even reach TDLib.

**Step 1: Write the failing test**

Hard to unit-test `Drop` (Rust has no Drop test infrastructure). Instead, add a doc-test / unit test that:

1. Creates a `RealTelegramClient` (mock variant — TBD).
2. Drops it.
3. Asserts that the receive loop's `running` flag is set to `false` and that the receive loop exits within 100 ms.

This requires exposing a `is_running()` accessor on `RealTelegramClient` (or a feature-gated test-only one). Alternatively, document the fix and rely on `cargo test` to assert no deadlock.

For now: add a test that constructs a `RealTelegramClient` via the (still-feature-gated) constructor with `use_test_dc` and a real-enough TDLib, then drops it, and asserts the receive loop's `running` flag transitions to `false` within 100 ms. Add a `#[cfg(test)]` accessor on `ClientState` for `running()`.

**Step 2: Implementation**

In `src/real_client.rs`:

- Add a `shutdown_tx: mpsc::Sender<()>` field to `ClientState`.
- In `ClientState::new`, create `let (shutdown_tx, shutdown_rx) = mpsc::channel(1);` and pass `shutdown_rx` to the receive loop.
- The receive loop, in its main `loop`, races `tokio::select!` on `shutdown_rx.recv()` and the existing `spawn_blocking(tdlib_rs::receive)` call. On shutdown, the loop calls `tdlib_rs::functions::close(client_id)` from within the existing tokio runtime (no nested runtime) and then exits.
- Remove the `impl Drop` block entirely — the `shutdown_tx` is dropped when the last `RealTelegramClient` clone is dropped, which signals the receive loop to shut down.
- Wait — `RealTelegramClient` is `Clone`, and shutdown on last-drop is tricky. Keep `Drop` but make it non-blocking: `Drop` sends `()` on `shutdown_tx` (non-blocking) and stores `client_id` somewhere for the receive loop to close. OR: send `(client_id, ())` so the receive loop knows which client to close.

Simplification: keep `Drop` simple. On `Drop`, send `(client_id, ())` on a `mpsc::Sender<(i32, ())>` channel. The receive loop `select!`s on this and on `tdlib_rs::receive`. When it receives a shutdown signal, it calls `tdlib_rs::functions::close(client_id).await` and exits.

But this still requires the receive loop to be the one to call `close`, which means the receive loop must outlive the last `RealTelegramClient` clone's `Drop`. The receive loop holds an `Arc<ClientState>`, so it lives as long as the `Arc`. The `shutdown_tx` is in the `Arc`, so the receive loop can pull from it. But `shutdown_tx.send` is async — `Drop` can't `.await`. Use `try_send` (non-blocking). If the channel is full, the shutdown is a no-op (the next process exit will reclaim).

Final design: `shutdown_tx: mpsc::Sender<ClientId>` in `ClientState`. `Drop` does `let _ = self.state.shutdown_tx.try_send(self.state.client_id);`. Receive loop `select!`s on `shutdown_rx.recv()` and the receive call. On shutdown signal, calls `close(client_id)`. No detached thread.

**Step 2: Implementation**

In `src/adapter.rs:265-295`:

```rust
async fn upload_media(
    &self,
    filename: &str,
    data: &[u8],
    _mime_type: &str,
) -> Result<String, PlatformAdapterError> {
    // Ambiguity guard: if multiple domains are registered, force the caller
    // to use upload_media_to_domain.
    let domains: Vec<_> = self.domain_chat_ids.read().unwrap().keys().copied().collect();
    if domains.len() > 1 {
        return Err(PlatformAdapterError::Unreachable {
            platform: "telegram".into(),
            reason: "multiple domains registered; use upload_media_to_domain".into(),
        });
    }
    if let Some(hash) = domains.first() {
        let domain = BroadcastDomainId { domain_hash: *hash, platform: PlatformType::Telegram };
        return self.upload_media_to_domain(&domain, filename, data, _mime_type).await;
    }
    Err(PlatformAdapterError::Unreachable {
        platform: "telegram".into(),
        reason: "no registered domain for upload_media".into(),
    })
}

async fn upload_media_to_domain(
    &self,
    domain: &BroadcastDomainId,
    filename: &str,
    data: &[u8],
    _mime_type: &str,
) -> Result<String, PlatformAdapterError> {
    let chat_id = self.chat_id_for_domain(domain).ok_or_else(|| {
        PlatformAdapterError::Unreachable {
            platform: "telegram".into(),
            reason: "domain not registered".into(),
        }
    })?;
    self.client
        .send_document(&chat_id, filename, data)
        .await
        .map_err(|e| PlatformAdapterError::Unreachable {
            platform: "telegram".into(),
            reason: e.to_string(),
        })
        .map(|s| s.id)
}
```

Note: this is a method on the impl, not on the `PlatformAdapter` trait. The gateway can call it via the concrete `TelegramAdapter` type.

```rust
            .lock()
            .unwrap()
            .push(TelegramUpdate::NewMessage(NewMessage {
                chat_id: chat_id.parse().unwrap_or(0),
                message: encoded,
                from: String::new(),
            }));
    }
    let mut pending = self.pending_updates.lock().unwrap();
    Ok(std::mem::take(&mut *pending))
}
```

```rust
    loop {
        match tdlib_rs::receive() {
            Some((update, client_id)) => {

        }
```
