## In Scope

Per RFC-0958 §Implementation Phases B.2 + C.2 + D + E + F + G + S05 plan §3 Steps 1–8:

1. **Cairo circuit** (`cairo/src/lib.cairo` under scarb package `capability_zk`):
   - Public input struct: `CapabilityClaim { ask_id, axes_consumed, cap_root_hash, invocation_hash, holder_did, current_unix_time, provider_slot_id }`
   - Private witness: full macaroon chain + discharges + capability caveats + (optionally) inference trace
   - Structural binding to public inputs (see `## R4 Rebuttal Register` C1 for honest disclosure: the shipped Cairo `main()` returns `1` after structural field-bounds checks; HMAC-BLAKE3 chain re-derivation, Ed25519 holder-sig verify, and Poseidon inference-trace binding are deferred to follow-up mission `0958-b-real-cairo-crypto.md`).
   - Compiled via `scarb build` (Cairo 2.x; standalone `cairo-compile` binary does not exist post-Cairo-1.x).

2. **CASM compilation** (`crates/zk-circuit/`):
   - `scarb build` → `cairo/target/dev/capability_zk.sierra.json`
   - In-process Sierra→CASM pass via `cairo-lang-sierra-to-casm` 2.20.0 + `cairo-lang-sierra-type-size` 2.20.0 + `cairo-lang-sierra` 2.20.0
   - `compile_from_source(BUNDLED_CAIRO_SOURCE) -> Result<CompiledCircuit, HashError>`; `bundled_casm_bytes()` + `bundled_casm_hash_hex()` memoize via `OnceLock<Result<…, HashError>>`
   - `BUNDLED_CAIRO_SOURCE = include_str!("../../../cairo/src/lib.cairo")`
   - Hard-fail on missing scarb / cairo-lang-* deps — `bundled_casm_hash()` panics loudly with actionable message; no silent stub
   - `crates/zk-circuit/tests/casm_snapshot.rs`: shape + 64-hex + determinism + tamper detection + OnceLock memoization + include_str! path resolution
   - `max_bytecode_size = 50 * 1024` enforced (R4 HIGH fix; AC-12 50KB lower bound)

3. **STWO FFI bridge** (`crates/zk-vendor/stwo-sys/` + `crates/zk-vendor/src/lib.rs`):
   - `stwo-sys/` separate cdylib cargo project (workspace-excluded) with nightly `rust-toolchain.toml` pinning `nightly-2025-06-23`
   - `crates/zk-vendor/src/lib.rs::loaded_library() -> Option<StwoSys>` libloading's `libstwo_sys.so` at runtime
   - `BackendKind { Ffi, Stub }` enum; `BackendKind::Stub` returned when FFI lib absent
   - Build command: `cargo +nightly-2025-06-23 build --release --manifest-path crates/zk-vendor/stwo-sys/Cargo.toml`

4. **Verification wrapper** (`crates/quota-router-core/src/zk_verify/capability.rs`):
   - `verify_capability_zk(stark_proof: &StarkProof, public_inputs: &CapabilityClaim) -> Result<()>`
   - CipherOcto-domain gating: public-input equality (constant-time, R4 HIGH fix), CASM hash drift, clock skew, `provider_slot_id` slot binding (R4 cross-slot defense)
   - Delegates STWO-level verify to `zk-verifier`; layered FFI > Stub
   - `provider_slot_id` drift → `PublicInputMismatch` (RFC-0958 v1.4 IA-11 cross-slot defense)

5. **Mint API + NodeType gating** (`crates/octo-wallet/src/capability/zk_mint.rs`):
   - `mint_with_zk_and_signers(witness, public_inputs, casm_hash, signers) -> Result<ProofBundle, ZkMintError>`
   - Wholesale → REJECT (`NodeTypeCannotMintZKCap`)
   - SelfHost → DEFAULT ZK (mint requires `inference_trace` in witness)
   - Hybrid → OPT-IN (explicit `mint_with_zk()` call)
   - `CapabilityClassRegistry` rejects Wholesale + ZKBearing registration (`RegistryError::WholesaleCannotRegisterZK`)
   - `bundled_casm_hash()` calls `zk_circuit::compile_from_source(BUNDLED_CAIRO_SOURCE)` via private `compute_bundled_casm_hash` helper; panics with original `compiler_internal` error string surfaced
