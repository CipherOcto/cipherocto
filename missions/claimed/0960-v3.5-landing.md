# Mission `0960-v3.5-landing` v1.0 — OPEN 2026-08-24

## Context

RFC-0960 v3.5 (`rfcs/accepted/economics/0960-v35-vault-path-taxonomy.md`, Accepted 2026-08-23) adds the Vault Path Taxonomy amendment on top of RFC-0960 v3.0 substrate (landed via `0960-vault-substrate-amendment` 2026-08-18). v3.5 introduces:

- **Mesh Open Path** (chain_namespace=0x01) — open-set membership via capability-gated policy kind
- **Corporate Closed Path** (chain_namespace=0x02) — closed-set membership per RFC-0967-A1 §2.6
- **5 policy Kinds** registered per RFC-0967-A1 §2.6 kind UUID registry:
  - `octo/membership/capabilitygated/v1` — mesh open path membership gate
  - `octo/interop/none/v1` — no-bridge interop default (mesh)
  - `octo/burn/timelock/v1` — 24h timelock burn (FATF Travel Rule + MiCA Article 23)
  - `octo/audit/mainnet/v1` — v1 audit kind (mesh)
  - `octo/audit/ab/v1` — v2 audit kind (mesh)
- **4 substrate tables** (PENDING per RFC-0960 v3.5 §0 Status): `chain_metadata`, `ledger_chain_registry`, `policy_registry`, `policy_kind_authority`
- **ValueTransfer trait** (PENDING per RFC-0960 v3.5 §0 Status) — Layer B primitive, additive to RFC-0206 §4 additive-only migration rule

The previous concrete mission reference (`0206-001`) was textual drift per v3.5 §0 Status header: `0206-001` is Layer A storage-core, not vault DDL. Correct landing ownership = research §16 mission `vault-chain-metadata` Phase 1 substrate work + this mission `0960-v3.5-landing` for RFC text cross-link + RFC-0967-A1 §2.6 kind UUID registry.

## Scope

### Step 1: DDL `chain_metadata` table (NEW substrate)

New file `crates/octo-vault/migrations/v015__chain_metadata.sql`:

```sql
-- Mesh Open Path vs Corporate Closed Path distinction enforced via chain_namespace byte.
-- Per RFC-0960 v3.5 §2.1 + §2.2 + RFC-0010 §2 ledger_chain_registry DDL:
--   0x01 = Rfc namespace (currently only "cipherocto-mainnet" canonical literal)
--   0x02 = User namespace (partner-mainnet etc.)
--   0x03-0xFF = Reserved (rejected by NamespaceVariant::from_canonical_bytes per octo-ident/src/chain.rs)
CREATE TABLE chain_metadata (
    chain_id BLOB(32) NOT NULL PRIMARY KEY,
    chain_namespace BLOB(1) NOT NULL CHECK (chain_namespace = x'01' OR chain_namespace = x'02'),
    chain_namespace_label TEXT NOT NULL,
    registration_unix BIGINT NOT NULL,
    registrar_did TEXT NOT NULL,
    metadata BLOB,
    CONSTRAINT fk_chain_id FOREIGN KEY (chain_id) REFERENCES ledger_chain_registry(chain_id)
);
```

Per R5 fix-all (RFC-0010 VH row 5): "0x01 Mainnet" label REMOVED. chain_namespace byte mapping = `0x01 → Rfc` (substrate `NamespaceVariant::Rfc`) and `0x02 → User` (substrate `NamespaceVariant::User`).

### Step 2: DDL `ledger_chain_registry` table (RFC-0010 §2 substrate)

New file `crates/octo-vault/migrations/v015__chain_metadata.sql` (same migration file — additive, single deploy unit):

```sql
CREATE TABLE ledger_chain_registry (
    chain_id BLOB(32) NOT NULL PRIMARY KEY,
    canonical_label TEXT NOT NULL UNIQUE,
    namespace_kind BLOB(1) NOT NULL CHECK (namespace_kind = x'01' OR namespace_kind = x'02'),
    registration_authority TEXT NOT NULL,  -- RFC-0010 v17 chain-id registration authority substrate
    registered_at_unix BIGINT NOT NULL,
    revoked_at_unix BIGINT
);
```

### Step 3: DDL `policy_registry` + `policy_kind_authority` (RFC-0967-A1 §2.5)

New file `crates/octo-vault/migrations/v016__policy_registry.sql`:

```sql
CREATE TABLE policy_registry (
    policy_kind_uuid BLOB(16) NOT NULL PRIMARY KEY,  -- UUIDv5 namespace seed
    policy_kind_string TEXT NOT NULL UNIQUE,         -- "octo/membership/capabilitygated/v1" etc.
    authority_kind BLOB(1) NOT NULL,                 -- policy_kind_authority byte
    registered_at_unix BIGINT NOT NULL,
    revoked_at_unix BIGINT,
    metadata BLOB
);

CREATE TABLE policy_kind_authority (
    authority_uuid BLOB(16) NOT NULL PRIMARY KEY,
    authority_kind BLOB(1) NOT NULL,
    delegate_to_policy_kind_uuid BLOB(16),
    registered_at_unix BIGINT NOT NULL,
    revoked_at_unix BIGINT,
    CONSTRAINT fk_authority_uuid FOREIGN KEY (delegate_to_policy_kind_uuid) REFERENCES policy_registry(policy_kind_uuid)
);
```

5 policy Kinds to seed per RFC-0967-A1 §2.6: `octo/membership/capabilitygated/v1`, `octo/interop/none/v1`, `octo/burn/timelock/v1`, `octo/audit/mainnet/v1`, `octo/audit/ab/v1`. UUIDv5 derivation: `BLAKE3("cipherocto/policy/kind/v1/" + policy_kind_string)` first 16 bytes.

### Step 4: `ValueTransfer` trait (Layer B primitive)

New file `crates/octo-vault/src/transfer.rs`:

```rust
//! ValueTransfer trait surface per RFC-0960 v3.5 §0 Status (PENDING landing).
//!
//! Additive to RFC-0206 §4 Layer B additive-only migration rule. Re-exports
//! existing `transfer_events` substrate (v014 migration) through a typed trait.

use octo_determin::Dqa;

/// Cross-chain value transfer primitive (RFC-0960 v3.5 §0 + RFC-0959 v2.0 cross-chain
/// settlement reject per `0959-c1-wire-A-substrate-verify`).
#[async_trait::async_trait]
pub trait ValueTransfer: Send + Sync {
    /// Build a `ValueTransferEnvelope` from `(from_vault_id, to_vault_id, amount, chain_id)`.
    fn build_envelope(
        &self,
        from_vault_id: [u8; 32],
        to_vault_id: [u8; 32],
        amount: Dqa,
        chain_id: [u8; 32],
    ) -> ValueTransferEnvelope;

    /// Apply a `ValueTransferEnvelope` to substrate; consumes the v014 `transfer_events`
    /// log writer + chain_metadata `chain_id` FK check + RFC-0959 v2.0 settlement reject.
    async fn apply(&self, envelope: &ValueTransferEnvelope) -> Result<(), TransferError>;
}

pub struct ValueTransferEnvelope {
    pub from_vault_id: [u8; 32],
    pub to_vault_id: [u8; 32],
    pub amount: Dqa,
    pub chain_id: [u8; 32],
    pub settled_at_unix: u64,
    pub transfer_event_id: [u8; 32],
}
```

`octo-vault/src/lib.rs` `pub use transfer::{ValueTransfer, ValueTransferEnvelope, TransferError}`.
