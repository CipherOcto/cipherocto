# body-hash-domain-prepend — actually prepend BODY_HASH_DOMAIN to body_hash inputs

**Status:** claimed (2026-08-27)
**Substrate:** RFC-0960-v36 §2.2 (BurnEventRef body_hash — `compute_body_hash` helper, canonical substrate home) + RFC-0959 §2.2 (SettlementEvent body_hash — `compute_settlement_body_hash` helper hosted within §2.2's code block alongside the scale-resolution error variants)
**Parent:** R3 review follow-on (cross-protocol domain-isolation finding)
**Depends on:**

- Mission F (`0960-v36-burn-event-dqa-migration-substrate.md`) — `compute_body_hash` in `crates/octo-policy/src/burn_event.rs`
- Mission G (`0959-v28-settlement-cost-dqa-migration-substrate.md`) — `compute_settlement_body_hash` in `crates/quota-router-sm-engine/src/settlement_event.rs`

## Motivation

Two body-hash functions reserve `BODY_HASH_DOMAIN` constants for cross-protocol isolation but never actually prepend them to the hash input:

- `crates/octo-policy/src/burn_event.rs` — `const BODY_HASH_DOMAIN: &[u8] = b"cipherocto/burn/v1/";` (19 bytes) is `dead_code` (the `const _: &[u8] = BODY_HASH_DOMAIN;` anchor exists only to silence the lint).
- `crates/quota-router-sm-engine/src/settlement_event.rs` — `const BODY_HASH_DOMAIN: &[u8] = b"cipherocto/settlement/v1/";` (25 bytes) is `#[allow(dead_code)]`.

Without domain separation, a hash collision is theoretically possible between a `BurnEventRef` body and a `SettlementEvent` body (or any other protocol using blake3 over a similar field concatenation). Cross-protocol isolation via per-protocol domain prefixes is mandatory; the substrate constants are reserved exactly for this purpose but unused.

## Scope

Prepend `BODY_HASH_DOMAIN` to the `buf` accumulator in BOTH functions, before any field extension.

### Sub-steps

1. **BurnEventRef `compute_body_hash`** — `crates/octo-policy/src/burn_event.rs`. Insert `buf.extend_from_slice(BODY_HASH_DOMAIN);` as the FIRST line of the body (before `chain_id` extension). The `Vec::with_capacity` must increase by `BODY_HASH_DOMAIN.len()` (19 bytes for the burn domain).
   ```rust
   pub fn compute_body_hash(burn: &BurnEventRef) -> [u8; 32] {
       let mut buf: Vec<u8> = Vec::with_capacity(BODY_HASH_DOMAIN.len() + 32 * 6 + 1 + 8 + 8 + 8 + 32 + 8 + 32);
       buf.extend_from_slice(BODY_HASH_DOMAIN);
       buf.extend_from_slice(burn.chain_id.as_bytes());
       // ... rest unchanged
   }
   ```

2. **SettlementEvent `compute_settlement_body_hash`** — same pattern: prepend `BODY_HASH_DOMAIN` (25 bytes for settlement domain). `Vec::with_capacity` adjustment.
   ```rust
   pub fn compute_settlement_body_hash(settlement: &SettlementEvent) -> [u8; 32] {
       let mut buf: Vec<u8> = Vec::with_capacity(BODY_HASH_DOMAIN.len() + 32 * 6 + 1 + 16 + 8 + 8 + 32 + 32);
       buf.extend_from_slice(BODY_HASH_DOMAIN);
       buf.extend_from_slice(settlement.settlement_id.0.as_ref());
       // ... rest unchanged
   }
   ```

3. **Remove the dead_code anchor** — the `const _: &[u8] = BODY_HASH_DOMAIN;` anchor in `crates/octo-policy/src/burn_event.rs` is REMOVED. The `#[allow(dead_code)]` attribute on `BODY_HASH_DOMAIN` in `crates/quota-router-sm-engine/src/settlement_event.rs` is REMOVED (the constant is now used).

4. **Test vector updates** — existing TV-BE tests (`compute_body_hash_returns_same_for_equal_inputs` / `compute_body_hash_distinguishes_assets`) assert hash equality / inequality for input variants. Domain prepend does NOT change those properties (same domain → same prefix; different inputs → still different hashes). Tests MUST pass without modification. **However:** any test that hard-codes an expected hash value (byte-by-byte comparison against a precomputed `expected_body_hash`) MUST be regenerated. `grep -rn "expected.*body_hash\|expected_body_hash" crates/octo-policy/src/burn_event.rs crates/quota-router-sm-engine/src/settlement_event.rs` flags these.

5. **Wire-form on-chain hashes** — if `body_hash` is persisted anywhere (audit-log row, transfer-event envelope), the on-disk bytes MUST be regenerated by the new function. Migration runner at `crates/octo-vault/migrations/` — if a body_hash column exists, add a migration step to recompute (CYCLE-2 of mission per RFC-0960 §5 etiquette). **Verify:** `grep -rn "body_hash" crates/octo-vault/migrations/` to confirm no persisted body_hash column exists; if absent, no migration needed.

6. **Pre-landing on-chain audit gate** — sub-step 5's grep gate runs BEFORE step 1's `Vec::with_capacity` change. If any persisted body_hash column exists, the mission blocks until the feature-flag migration path (Backward compat section) is implemented.

## Out of Scope

- Changing the domain separator strings (`"cipherocto/burn/v1/"` / `"cipherocto/settlement/v1/"` are RFC-frozen; bumping to `v2/` is a separate RFC)
- Adding domain separation to OTHER hash functions (e.g., `compute_payment_body_hash` if it exists; tracked separately)
- Domain separation across protocol boundaries (`BurnEventRef` body vs `SettlementEvent` body — different domains already; cross-protocol isolation between CipherOcto and external systems tracked at a separate RFC)

## Backward compat

- **Wire form:** `body_hash` field values CHANGE for all existing events (prepend changes blake3 input). Justified per `cipherocto-design-principles` §No premature coupling + the substrate was unfinished (constant reserved but unused).
- **Persisted body_hashes:** If any, regeneration migration required (sub-step 5). If absent, no impact.
- **Signature verification:** Existing signatures over old body_hash values are INVALIDATED by this change. Audit batch replay path (per `cipherocto-design-principles` §Attenuation invariants cross boundaries — replay must re-run against the new domain-prefixed function) MUST be re-executed post-migration. **Risk callout:** if any on-chain body_hash exists at landing time, the migration is HIGH-RISK and MUST be gated behind a feature flag (`legacy_body_hash_v1` / `body_hash_v2`) for one release cycle, mirroring the 3-cycle deprecation pattern described within RFC-0960 §5 (Single Timeline). The sub-step 6 pre-landing audit gate enforces this. **Hard guard (mirrors `cache-bus-auth.md` `accept-unauthenticated`):** the back-compat `legacy_body_hash_v1` path is gated behind `#[cfg(debug_assertions)]` so `cargo build --release` physically cannot link it. Without this guard, the 1-cycle window becomes a permanent production default (CVSS-relevant — pre-domain hash collision forge). Documented in `Cargo.toml` feature description. The flag is a debug-only escape hatch, NOT a release-grade toggle.

## Risk

- HIGH if body_hash is on-chain: signatures over old hashes break. Mitigation: feature flag + 1-cycle deprecation window.
- MEDIUM if body_hash is in audit log only: audit replay fails until re-run. Mitigation: clear audit-log table + regenerate.
- LOW if body_hash is computed-on-the-fly only (no persistence): zero migration cost, just regenerate.
