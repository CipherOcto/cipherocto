## Summary

Author the byte-exact test vector fixture `tests/fixtures/phase1_tv.json`
that gates Phase 1 acceptance for RFC-0009 v1.2. Per R17 M3:
RFC-0862 v1.3.0 fixture lives in a SEPARATE file
`tests/fixtures/phase1_tv_0862.json` covered by separate mission
(see Cross-references). This mission covers RFC-0009 Phase 1 TVs
ONLY.

## Acceptance Criteria

- [ ] `tests/fixtures/phase1_tv.json` exists at repo root.
- [ ] JSON contains entries for `TV-1`, `TV-2`, `TV-3` (RFC-0009 v1.2
      Phase 1 TV) ONLY — RFC-0862 TVs go in `phase1_tv_0862.json`.
- [ ] Each TV entry has structure:
      - `name`: human-readable identifier
      - `inputs`: hex-encoded byte sequences (seeds, audience DIDs,
        channel IDs, parent capability keys, threshold params,
        HLC inputs, etc.)
      - `outputs`: hex-encoded derived outputs (HKDF output bytes,
        aggregated signature bytes, HLC timestamps, WriterIdentity
        bytes, etc.)
      - `verification_command`: exact `cargo test` invocation that
        reproduces the expected output
- [ ] All TVs are byte-exact reproducible (reference implementation
      re-derives outputs deterministically per RFC-0008 Class A
      determinism).

## Implementation Guide

Reference impl: `crates/octo-wallet/` + `octo-sync/`. Use the
`borsh` crate for serialization. Each TV is generated by:

1. Run reference impl with TV inputs.
2. Capture exact byte output (HKDF, signature, HLC).
3. Encode as hex in JSON fixture.
