## Summary

This sub-amendment carries controller-level codepoint reservations for two items the parent RFC-0968 §28 has not yet addressed:

- A first amendment recording canonical `ControllerIdMissing = 0x34` (substrate-verified at `crates/octo-reputation/src/error.rs:217`; original `0x2E` already held by `RotationProvenanceMissingTombstoned` per `error.rs:193`)

These amendments were not previously enumerated as numbered rows in parent RFC-0968 §28; this sub-amendment assigns them row numbers 28 + 29 (next sequential after parent §28 row 27) for traceability. The sub-amendment file exists for the filing gate authority established by research doc §20 decision #1; per parent §28 amendment procedure, on Accept the rows fold in place into parent RFC-0968 (amendment 28 → parent §13 error discriminant table row; amendment 29 → parent §28.6 governance-identity derivation subsection or new §28.8) and this file is archived.

## §2 Governance Quorum Carryover

Closed by parent RFC-0968 §28 amendment 26 (Session 1 I-5): `GOVERNANCE_QUORUM = 3` constant + `GovernanceProof.governance_set_hash: [u8; 32]` field. Implementation MUST verify the active-set digest at the snapshot where `governance_pubkey` is active. Single-key-compromise attack closed.

Closed by parent RFC-0968 §28 amendment 27 (trusted-clock wrapper): caller-supplied `now_unix` is rejected at public RPC entrypoints; the receiving service supplies its trusted-clock value. Suspension/resume/rotation proofs carry the timestamp inside the signature, not as a separate parameter. Closes stale-proof replay.

Both amendments 26 + 27 are informational carryover (already folded into parent §28 per the parent §28 in-place folding convention). No A2 §1 amendment table rows are added for these; parent §28.7 line 3158 OQ-V4 closure record applies.

## §3 Reserved Codepoint Range — Parent §13 vs Substrate Drift

**Parent RFC-0968 §13 table** documents discriminants `0x01..=0x29` per line 2641 (parent does not claim source-order monotonicity of the substrate; A2 makes no claim about monotonicity either); parent explicitly states `0x2A..=0xFF are reserved for future variants` per Round 10 M1.

**Substrate `crates/octo-reputation/src/error.rs`** implements variants beyond parent §13's documented range:

| Codepoint | Variant                               | Source line    | Parent §13 status                                                                         |
| --------- | ------------------------------------- | -------------- | ----------------------------------------------------------------------------------------- |
| `0x33`    | `AnchorSubmitterRejected(String)`     | `error.rs:181` | unassigned (parent reserved `0x2A..=0xFF`) — substrate drift                              |
| `0x34`    | `ControllerIdMissing`                 | `error.rs:217` | unassigned (parent reserved `0x2A..=0xFF`) — substrate drift; ratified by A2 amendment 28 |
| `0x3A`    | `GossipEnvelopeInvalid(&'static str)` | `error.rs:223` | unassigned (parent reserved `0x2A..=0xFF`) — substrate drift                              |

Substrate doc-comment internally describes two contradicting assigned-range ceilings: `error.rs:4` says `0x01..=0x3A` matches "post-amendment RFC table"; `error.rs:11` says real-variant ceiling is `0x39` "Per amendment 82". The "amendment 82" reference is **substrate-local** (not in parent RFC §28 which runs rows 1-27) and is recorded here for traceability only — A2 does NOT propagate this as an RFC amendment number. Substrate `is_reserved()` (function defined at lines 283-287; called at line 425 in `controller_id_missing_round_trips_to_0x34` and lines 443-446 in `reserved_range_is_3b_to_ff`) treats `0x3B..=0xFF` as reserved, returning `false` for `0x3A`, `0x34`, `0x32`.

Of the 17 codepoints `0x2A..=0x3A` that would be the next-block reservation after the §13 table ceiling, substrate implements 3 (`0x33, 0x34, 0x3A`). The remaining 14 codepoints are reserved by parent §13 but unassigned by name.
