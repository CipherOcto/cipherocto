## Summary

Adds `Commands::Network { NetworkAction }` to `octo` CLI (RFC-0011). 17 substrate-faithful subcommands delegate to real `octo-network` types/methods, verified by substrate-faithfulness audit (see §Implementation Phases Phase 6).

5 functional families; `bind-envelope` straddles Bootstrap + Discovery + Envelope by substrate module; it lives across `mon/bind_envelope.rs` + `mon/rebind.rs` and crosses module boundaries (NOT organised by functional family):

| Family                | Subcommands                                                                                                                    | Substrate                                                                |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| Bootstrap + Discovery | `peers`, `identity`, `mode`, `authority`, `discovery` (RFC-0851 governs `peers` + `identity`; RFC-0855 §8 governs `discovery`) | `mon/bootstrap.rs`, `mon/discovery.rs`, `gdp/cache.rs`, `dot/gateway.rs` |
| Trust + Reputation    | `trust-graph`, `slash`                                                                                                         | `mon/trust_graph.rs`, `reputation/slash_store.rs`                        |
| Coordinator           | `coordinator`                                                                                                                  | `mon/coordinator.rs`, `octo_coordinator_types`                           |
| Governance            | `governance`                                                                                                                   | `mon/governance.rs`, `mon/governance_rotation.rs`                        |
| Envelope              | `bind-envelope` (all 4 ops: `show`, `rebind-{prepare,commit,abort}`)                                                           | `mon/bind_envelope.rs`, `mon/rebind.rs`                                  |

Every subcommand is Layer C façade over real `octo-network` (Layer B) call. No CLI reach into substrate internals; all cross typed substrate boundary per [[cipherocto-design-principles]] §Stable Abstractions Principle.

Subcommands documented "DEFERRED (substrate-additions prerequisite)" NOT in binary surface; available only after paired companion mission closes its DRY CLOSED gate.

## Motivation

0011-deprecation-stub-removal removed `octo init` / `octo join` / `octo status`, with user-accepted deferral of `octo network bootstrap` + `octo network status` to this amendment (`0011-deprecation-stub-removal` §Out of Scope), scoped to the substrate-faithful slice only with `bootstrap` + `status` still gated on companion G1 per §Substrate-Additions Companion Missions.

`docs/audits/network-cli-gap-recon.md` identified 21 GAPs between `octo-network` substrate and current `Commands` enum (which has NO `Network { NetworkAction }` variant). Substrate-faithfulness reviews confirmed 17 substrate-faithful subcommands map to real `octo-network` substrate; the remaining GAPs are substrate-missing and become explicit companion missions (§Substrate-Additions Companion Missions).

3 concrete operator gaps:

1. **Bootstrap config observability.** Operators edit `$OCTO_HOME/octotransport/bootstrap.toml` for `BootstrapMode` + `SeedListAuthority` but have no CLI surface. Substrate `BootstrapMode` enum + `verify_authority(SeedListAuthority, epoch)` + `SlashedSeedBlacklist` exist; CLI binding does not.
2. **Network state observability.** Operators have no CLI surface for `GatewayCache` entries, trust-graph topology, slash reputation stats, coordinator lifecycle, governance tally. They grep substrate logs. Substrate functions exist for all 17 substrate-faithful subcommands.
3. **Mutating operations unsafe.** Substrate-faithful slice has 3 mutating subcommands (the `bind-envelope rebind-{prepare,commit,abort}` payload builders); every one must mirror §Confirmation Flag Matrix; every mutating subcommand defaults to `--dry-run`. (`slash mark` is out of scope per RFC-0008 §Execution Class Mapping; future amendment would surface the inquiry half.)

Confirmation-flag ladder (pastejacking defense):

1. Operator invokes write subcommand → CLI emits dry-run preview to stdout/stderr.
2. Operator reads preview. The preview includes the dispatch summary (subcommand + flags + target surface + substrate surface to mutate).
3. Operator re-invokes with `--confirm-acknowledge`. CLI confirms operator read the preview; CLI emits second confirmation prompt.
4. **For pastejacking-risk writes only:** operator re-invokes with BOTH `--confirm-acknowledge` AND `--confirm` in the SAME invocation. The two-flag pattern breaks the clipboard-pastejacking attack: a pastejacked flag string lands `--confirm-acknowledge` but not `--confirm`, so the CLI gate still holds. Operator must type `--confirm` from scratch after reading the preview.

CI mode (operator role = `CI` per §Per-Subcommand Capability Caveat Matrix) NEVER bypasses the `--confirm-acknowledge` gate for the 5 CI-DENY-default subcommands below; CI agents hit exit 90 (`NetworkCIRebindDenied`) per §Error Handling row 90 regardless of `--confirm-acknowledge` presence AND regardless of subcommand reversibility[^ci-gate-precedence]. The 5 CI-DENY-default subcommands are `bind-envelope rebind-{prepare,commit,abort}` + `mode set` + `authority rotate`. CI agents cannot author bind-envelope state changes (reversible or not) nor bootstrap lifecycle changes. This is a defense-in-depth measure, not a substitute for human review.

The `--dry-run` default is operator-friendly: every write preview is one `--dry-run` invocation away. The double-flag for pastejacking-risk writes is pastejacking-defense-specific; not a usability burden for normal operators.

### Out-of-scope Roles

- **P2P gossip peers** — peer-to-peer propagation substrate exists (`mon/gossip.rs`), but peer-to-peer gossip NOT operator-facing. CLI exposes `gossip stats` DEFERRED until `Gossip::stats()` substrate lands.
- **Routing substrate operators** — `routing send` (onion relay, RFC-0863) + `router status` (quota marketplace, RFC-0870) DEFERRED until `NetworkSender` + `QuotaRouterNode` substrate land. Both are substrate-facing, not operator-facing CLI surfaces.
- **Election voting operators** — `election show` + `cast_vote` DEFERRED until `WriterElection` substrate lands (RFC-0862p-a substrate not yet implemented; G18 `0011-h-s-a-writer-election` companion mission).
- **Slash evidence creation** — operators cannot create `SlashEnvelope`s via CLI; `slash` subcommands are read-only per RFC-0008 §Execution Class Mapping.

### Binary Surface

Additive extension to `crates/octo-cli/src/lib.rs` `Commands` enum:

```rust
#[derive(Subcommand, Debug)]
#[non_exhaustive]
pub enum Commands {
  // ... existing variants (Whoami, Identity, Capability, Policy, Role,
  // Reputation, Mesh, Vault, Agent, Governance, Audit) ...

  /// Network operations subcommands (RFC-0011-h).
  ///
  /// Substrate-faithful slice of 17 subcommands delegating to
  /// `octo-network` Layer B functions. Defer-to-substrate-additions
  /// subcommands tracked in §Substrate-Additions Companion Missions.
  Network {
    /// Network subcommand.
    #[command(subcommand)]
    action: NetworkAction,
  },
}
```

```rust

pub enum NetworkAction {
  /// Known gateway peers (RFC-0851).
```

## Security Considerations

Narrative threat model; operator-facing decision matrix in §Adversarial Review (canonical cite for these bullets).

- **Envelope payload bytes never echoed (canonical invariant).** `bind-envelope show` returns metadata + `canonical_bytes_hash` only; raw `Vec<u8>` from `BindEnvelope::canonical_bytes()` NEVER surface in `OutputEnvelope` or logs. Invariant: `no-payload-bytes-leak`. Test vector: `tv-network-bind-envelope-show-1`.
- **Mutating subcommands gated + pastejacking defense.** All 3 `bind-envelope rebind-{prepare,commit,abort}` write subcommands require `--dry-run` default + `--confirm-acknowledge`; `rebind-commit` adds `--confirm` SECOND flag per §Confirmation Flag Matrix human column for high-blast-radius writes (pastejacking defense) per §Subcommand Taxonomy rebind-commit row.
- **Redaction placeholder form.** RFC-0011 §Redaction layer `[REDACTED:<kind>]` placeholders cover `[REDACTED:did]`, `[REDACTED:coordinator_id]`, `[REDACTED:gateway_id]`, `[REDACTED:canonical_bytes_hash]`. `file_path` + `domain_id` are scrubber-tracked per RFC-0011 §Redaction Layer. They surface scrubbed by default, never with `[REDACTED:<kind>]` form. Audit mode applies same placeholders.
- **`--allow-ci-rebind` escape hatch (CI only).** Hidden from `--help` per RFC-0011 §Test Vectors convention; surfaces in `octo network ... --help-all` for emergency CI override only; bypasses the pastejacking-defense CI gate documented in §CI Mode Rationale. Stable contract: experimental flag, surfaces in changelog as such, removed before v1.0. Operators MUST NOT script against this flag; substrate-level double-confirm gate is the canonical pastejacking defense.
- **Rebind substrate primitives (substrate-faithful).** Substrate `crates/octo-network/src/mon/rebind.rs` exposes 9 distinct primitives on `RebindCoordinator`:
  - `RebindCoordinator::commit_envelope(&self, signature: Vec<u8>) -> Option<RebindCommit>` — payload builder. Returns `None` when the coordinator state is not `CoordinatorState::Committing` (state-machine guard); signature `Vec<u8>` is passed through verbatim into `RebindCommit { ..., signature }` and verified by downstream caller, NOT by this primitive.[^rebind-substrate-guards]
  - `RebindCoordinator::mark_committed(&mut self)` — state-conditional state-transition guarded by `if self.state == CoordinatorState::Committing { self.state = CoordinatorState::Committed; }`. Called AFTER CLI builder produces a verified `RebindCommit` payload via `commit_envelope`. Double-call in `Committing` state is silent no-op (per-`if` no-op when not in `Committing`); safety is downstream caller responsibility per RFC-0871 §Algorithms.[^rebind-mark-committed-silent-noop]
  - `RebindCoordinator::abort(&mut self, reason: RebindAbortReason) -> CoordinatorState` — state-conditional state-return. Returns current state unchanged when in `Idle` + `Committed` + `Aborted` + `TimedOut`; otherwise transitions to `Aborted`. CLI MAY inspect the returned state to confirm rollback completed.
  - `RebindCoordinator::prepare_envelope(&self, signature: Vec<u8>) -> RebindPrepare` — infallible Prepare payload builder. Required by `bind-envelope rebind-prepare`.
  - `RebindCoordinator::abort_envelope(&self, signature: Vec<u8>) -> Option<RebindAbort>` — abort-side payload builder mirroring `commit_envelope`. Returns `None` when the coordinator state is neither `Aborted` nor `TimedOut` (i.e., still in `Preparing` or `Committing`); signature passed through verbatim.[^rebind-substrate-guards]
  - `RebindCoordinator::record_vote(&mut self, platform: &str, vote: PrepareVote) -> CoordinatorState` — vote recorder. Returns current state unchanged when not in `Preparing`; treats empty participants and unknown platform as implicit ABORT; otherwise appends the vote and may transition to `Committing` or `Aborted`.
  - `RebindCoordinator::check_deadline(&mut self, now_epoch: u64) -> CoordinatorState` — deadline transitioner. Transitions `Preparing` to `TimedOut` when the deadline has elapsed without quorum (state-machine guard: only acts when `self.state == CoordinatorState::Preparing`; non-`Preparing` calls return `self.state` unchanged per `crates/octo-network/src/mon/rebind.rs:238-241`). CLI MAY invoke before `commit_envelope` to ensure substrate state reflects deadline semantics.
  - `RebindCoordinator::quorum(&self) -> usize` — quorum-size accessor. Returns the configured quorum count for the current coordinator. CLI MAY inspect to decide whether to attempt `commit_envelope` (quorum insufficient ⇒ `commit_envelope` will return `None`).
  - `RebindCoordinator::wins_tie_break(&self, other_domain_id: &str) -> bool` — tie-break predicate. Returns `true` if `self.domain_id` lexicographically precedes `other_domain_id`. CLI MAY inspect for tie-resolution transparency.
- **CLI rebind-commit canonical sequence.** CLI invokes `commit_envelope` first, asserts `Some(_)` payload, then calls `mark_committed` to flip substrate state. CLI MAY also invoke `check_deadline` first to ensure substrate reflects deadline semantics. Two-step contract per test vector `tv-network-bind-envelope-rebind-commit-5`. `mark_committed` is a state-conditional assignment (no-op when not in `Committing`); double-commit safety is enforced by the CLI gate (the clap arm is the only registration surface, and the state-machine guard on `commit_envelope` rejects double-call attempts upstream of `mark_committed`).[^rebind-mark-committed-silent-noop]
- **Tally freshness.** Substrate-owned via `VotingTally` (struct defined in `crates/octo-network/src/mon/governance.rs`); CLI never caches across invocations. RFC-0011-g governs CLI attestation + vote calls, not the underlying `VotingTally` type surface.
- **Rebind ordering + input gates.** Substrate nonce + monotonic timestamp gate per RFC-0871 §Data Structures governs rebind ordering, with CLI builders emitting substrate-derived freshness so operators CANNOT inject arbitrary values, and double-commit protection enforced per §Subcommand Taxonomy rebind-commit row.
- **`--depth` clamp on `trust-graph render`.** CLI-side depth clamp 1-100 protecting substrate from OOM (substrate `TrustGraph::render(&self, GraphFormat) -> String` has zero depth awareness per substrate-faithfulness audit). `--depth 0` → exit 85; `--depth 1000000` → clamp 100 with warning; clap u32 parse error for negative values (exit 2 per §Confirmation Flag Matrix).
- **Substrate-gated authority surfaces.** `SeedListAuthority::rotate_post_fork` gates at substrate layer per RFC-0851p-a; CLI does not bypass. Slash envelopes are substrate-generated only. Operators cannot mint via CLI (`slash mark` is read-only inquiry). `authority show` surfaces `SeedAuthorityError::SeedListAuthorityDeprecated` Display verbatim when present (no secret material).
- **CLI scope boundaries + key compromise mitigation.** No private key access. `identity show` surfaces public-key-derived `GatewayIdentity` only. No multiaddr allowlist collision. `peers add` stays in `octo mesh peer add` per RFC-0011-f. Signing-identity key compromise mitigated by HSM (Hardware Security Module) wallet per RFC-0015-a §6.5 paired-acceptance bridge + G21 substrate enabling key rotation invalidating stale signatures.

## Compatibility

**Backward:** `Commands::Network { NetworkAction }` is purely additive under `#[non_exhaustive]`. No existing CLI command renamed/removed. `octo mesh peer` (RFC-0011-f) remains mesh peer-table surface; this amendment adds `octo network peers` for gateway-cache surface (different substrate function — `octo_mesh::peers` vs `octo_network::gdp::cache::GatewayCache::iter`).

**Forward:** Future amendments may add `NetworkAction` variants additively (e.g., `slash mark`, `mode set`, `authority rotate` once companion substrate-additions missions close).

**Post-v2.0 stub-removal script breakage:** `octo network bootstrap` and `octo network status` are DEFERRED: clap arm not registered. Operators calling either receive clap `unrecognized subcommand` (exit 2). Migration: reroute to G1 (bootstrap) and to per-substrate `octo network peers list` + `octo network trust-graph render` (status-equivalent visibility).

**Cross-binary:** Operators using Python SDK / HTTP proxy (when RFC-0917 lands) will get same substrate-faithful slice via REST/gRPC. CLI is operator escape hatch. Full schema parity is OUT OF SCOPE for this RFC; cross-binary parity owned by RFC-0917.

## Rationale

Substrate-faithful umbrella pattern chosen because:

1. **One CLI namespace for network family.** Per RFC-0011-a through RFC-0011-g pattern, each CLI surface gets top-level namespace. `octo network` is natural namespace for substrate-faithful slice.

2. **Substrate-faithful boundary.** CLI never reaches into substrate internals; every subcommand crosses typed façade per [[cipherocto-design-principles]] §Stable Abstractions Principle + §Attenuation invariants cross boundaries.

3. **Substrate-first ordering via companion missions.** Each deferred subcommand has explicit substrate-additions companion mission in §Substrate-Additions Companion Missions. CLI missions gated on companion mission closure per [[feedback-no-fabricated-commit-rule]] + [[feedback_no_guess_hard_check]].

4. **No central enum edit for extension-bearing types.** `NetworkAction` is `#[non_exhaustive]`; future amendments add variants additively. Per [[cipherocto-design-principles]] §Extension over enumeration.

5. **Layer discipline preserved.** All additions are Layer C (CLI). Zero Layer A (crypto + canonical) changes. Substrate Layer B unchanged by this amendment (substrate-additions companion missions land Layer B changes; each is own DRY cycle).

6. **Lesson encoded.** Earlier drafts of this RFC produced multiple CRIT substrate-faithfulness findings against speculative substrate surface. Per [[substrate-faithfulness-verification]], substrate must be verified by grep BEFORE RFC is drafted, not after. Current rewrite grounded in actual `octo-network` cargo grep output.

## Appendices

### Layer Direction Verification

Per [[cipherocto-design-principles]] §Stable Abstractions Principle + §No premature coupling:

- CLI (`octo-cli`, Layer C) → substrate (`octo-network` Layer B; `octo-mesh` Layer C per RFC-0011-f): ✅ via typed façade calls
- Substrate (Layer B) → CLI (Layer C): ❌ never (substrate does not know about CLI)
- CLI (Layer C) → persistence adapters (Layer D): ❌ CLI does not reach into Layer D directly
- Substrate (Layer B) → Layer D: ✅ substrate façade calls Layer D adapters

No reverse dependencies. No central enum edits. No per-extension crate pattern violations.

### Mission YAML Pattern Reference

Each CLI mission YAML in `missions/open/0011-h-network-*.md` follows RFC-0011-c companion mission pattern (single mission, multiple ACs, 2-round DRY minimum). Two pattern variants:

#### Pattern A — Substrate-faithful CLI mission (no BLOCKED deps)

Example: `0011-h-network-mode` (covers only `mode show`; substrate exists; no BLOCKED dep):

```markdown
---

description: octo network mode show subcommand per RFC-0011-h Phase 2
metadata:
  node_type: substrate-cli
  type: cli-substrate
  originSessionId: ...
  created:
  v: "1.0"
  depends_on:
    - RFC-0011-h
    - RFC-0851p-a

---
```

#### Pattern B — CLI mission with BLOCKED substrate-additions companion

When a CLI subcommand needs substrate that does NOT yet exist, the mission YAML adds an inline `depends_on:` note pointing to the substrate-additions companion mission. The companion mission is itself Pattern C (§Pattern C) and must close its DRY CLOSED gate before this CLI mission opens.

```markdown
---
name: 0011-h-network-bootstrap
description: octo network bootstrap subcommand per RFC-0011-h Phase 6
metadata:
  node_type: substrate-cli
  type: cli-substrate
  originSessionId: ...
  created:
  v: "1.0"
  depends_on:
    - RFC-0011-h
    - RFC-0851p-a
    - mission 0011-h-s-a-bootstrap-orchestrator (BLOCKED — must close first)
status: Open
---
```

#### Pattern C — substrate-additions companion mission (Layer B)

Each entry in §Substrate-Additions Companion Missions takes this shape. Single mission, multiple ACs, 2-round DRY minimum. The mission lands the missing substrate type/method BEFORE its paired CLI mission opens.
